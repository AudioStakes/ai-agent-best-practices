# UI 動作確認リスト

このチェックリストは、AI Agent Best Practices Knowledge Base のHTML表示を、後から自動テスト化できるように整理したものです。

## 想定環境

- PCブラウザ
  - Chromium系ブラウザ
  - Safari / Firefox でも表示崩れがないこと
- モバイルブラウザ
  - iOS Safari
  - Android Chrome
- ローカルサーバー
  - `./serve.sh` で起動
  - デフォルトは `0.0.0.0:8000`

## 起動・キャッシュ

- [ ] `./serve.sh` を引数なしで実行すると `0.0.0.0:8000` で起動する。
- [ ] `./serve.sh 8080` を実行すると `0.0.0.0:8080` で起動する。
- [ ] `./serve.sh 8080 127.0.0.1` を実行すると `127.0.0.1:8080` で起動する。
- [ ] ローカルサーバーはHTML / CSS / JSに対してキャッシュを避けるレスポンスヘッダーを返す。
- [ ] 各HTMLの `style.css` 読み込みURLにキャッシュ破棄用のクエリ文字列が付いている。
- [ ] 各HTMLの `term-popup.js` 読み込みURLにキャッシュ破棄用のクエリ文字列が付いている。
- [ ] CSS / JS 更新後、ページを再読み込みすると最新の表示・挙動が反映される。

## 文字化け

- [ ] 各HTMLの先頭付近に `<meta charset="utf-8">` がある。
- [ ] 記事タイトルが `01. ����...` のように文字化けして表示されない。
- [ ] 日本語本文、見出し、ナビゲーション、用語説明が文字化けしない。
- [ ] `domain-glossary.html` の日本語説明が文字化けしない。

## レスポンシブ表示・余白

- [ ] モバイル幅では左右余白が小さく、本文領域が画面幅を有効に使っている。
- [ ] モバイル幅では記事カードの内側余白が大きすぎない。
- [ ] モバイル幅で横スクロールが発生しない。
- [ ] PC幅では本文が広がりすぎず、読みやすい最大幅に収まる。
- [ ] コードブロックは画面からはみ出す場合、横スクロールで読める。

## Index

- [ ] `index.html` から全10本の記事HTMLへ移動できる。
- [ ] `index.html` から `domain-glossary.html` へ移動できる。
- [ ] 各記事ページから `index.html` へ戻れる。
- [ ] 各記事ページから `domain-glossary.html` へ移動できる。
- [ ] Markdown原文へのリンクがある場合、リンク切れになっていない。

## ドメイン用語リンク・ポップアップ共通

- [ ] ドメイン用語は通常リンクとは違う、控えめな点線下線で表示される。
- [ ] ドメイン用語の表示は本文の可読性を邪魔しない。
- [ ] ドメイン用語は初出だけでなく、本文中の全出現がポップアップ対象になっている。
- [ ] ドメイン用語をクリック / タップすると、その用語の説明ポップアップが表示される。
- [ ] ポップアップには、クリック / タップした用語に対応する説明文が表示される。
- [ ] ポップアップとコードブロックの背景色が明確に区別できる。
- [ ] ポップアップは本文やコードブロックに埋もれず、前面に表示される。
- [ ] ポップアップ外をクリック / タップすると、ポップアップが閉じる。
- [ ] Escキーを押すと、表示中のポップアップが閉じる。
- [ ] 用語リンクの遷移先は `domain-glossary.html#...` または `domain-glossary.md#...` の該当アンカーになっている。

## PC版ポップアップ

- [ ] PC幅では、ドメイン用語にホバーすると説明ポップアップが表示される。
- [ ] PC幅では、ドメイン用語にキーボードフォーカスしても説明ポップアップが表示される。
- [ ] PC幅では、ポップアップが用語の近くに表示される。
- [ ] PC幅では、ポップアップが画面端からはみ出さない。
- [ ] PC幅では、ポップアップが大きすぎず本文を読み続けられる。

## モバイル版ポップアップ

- [ ] モバイル幅では、ドメイン用語を1回タップするとポップアップが表示される。
- [ ] モバイル幅では、ポップアップは画面下部ではなく画面上部に表示される。
- [ ] モバイル幅では、ポップアップ内に対象用語名が表示される。
- [ ] モバイル幅では、対象用語名のラベルが `ドメイン用語:` になっている。
- [ ] モバイル幅では、ポップアップ右上に `×` ボタンが表示される。
- [ ] モバイル幅では、`×` ボタンをタップするとポップアップが閉じる。
- [ ] モバイル幅では、ポップアップ外をタップするとポップアップが閉じる。
- [ ] モバイル幅では、ポップアップ表示中に同じ用語を再度タップすると、用語集の該当箇所へ移動できる。
- [ ] モバイル幅では、ポップアップが画面幅からはみ出さない。
- [ ] モバイル幅では、ポップアップが本文から離れていても、どの用語の説明か分かる。

## domain-glossary 表示

- [ ] PC幅では `domain-glossary.html` が表形式で表示される。
- [ ] モバイル幅では `domain-glossary.html` が表形式ではなく、用語ごとのカード / 箇条書き形式で表示される。
- [ ] モバイル幅の用語集カードには English、Japanese、description、Avoid が読みやすく表示される。
- [ ] モバイル幅の用語集では、説明列が縦長の細い列にならない。
- [ ] `#agent` などのアンカー付きURLで開いたとき、PC幅では該当する表の行へ移動できる。
- [ ] `#agent` などのアンカー付きURLで開いたとき、モバイル幅では該当するカードへ移動できる。

## 重要度表示

- [ ] 記事内の重要度は数字ではなく `★★★★★` / `★★★★☆` のような星表記で表示される。
- [ ] 記事本文に `重要度:` というラベルが表示されない。
- [ ] 記事先頭に、星の意味を説明する文が表示される。
- [ ] 星の説明は、各記事の内容を読む前に目に入る位置にある。
- [ ] 星表記はスクリーンリーダー向けに意味が分かるラベルを持つ。

## 対象記事・出典リンク

- [ ] `対象記事` の記事タイトルは `articles.csv` のタイトルを使っている。
- [ ] `対象記事` の記事タイトルにはドメイン用語置換が適用されていない。
- [ ] `対象記事` の記事タイトルは、該当する記事URLへのリンクになっている。
- [ ] 出典リンクが複数ある場合も、リンク先が壊れていない。
- [ ] 会社名だけの出典リンクがある場合、本文の読みやすさを邪魔しない位置にある。

## 会社ごとの主張の表示

- [ ] 会社ごとの主張は、長い横並びの文章ではなく、会社別の箇条書きで表示される。
- [ ] 会社名は太字または見出しとして識別しやすい。
- [ ] 各社の主張は短い箇条書きで2〜3点程度に整理されている。
- [ ] 共通する結論が必要な箇所では、会社別箇条書きの後に短くまとめられている。
- [ ] モバイル幅でも会社別の主張が読みやすい。

## Markdown / HTML 整合性

- [ ] Markdown版とHTML版で記事の主旨が一致している。
- [ ] Markdown版のドメイン用語リンクが壊れていない。
- [ ] HTML版のドメイン用語ポップアップに、Markdown版のリンク先と同じ用語説明が表示される。
- [ ] Markdown版とHTML版で重要度の星表記が一致している。
- [ ] Markdown版とHTML版で対象記事リンクが一致している。

## アクセシビリティ

- [ ] ドメイン用語リンクはキーボードでフォーカスできる。
- [ ] フォーカス時に視覚的なアウトラインが表示される。
- [ ] ポップアップの閉じるボタンはキーボード操作できる。
- [ ] ポップアップの閉じるボタンにはアクセシブルなラベルがある。
- [ ] リンク文字色と本文色、背景色のコントラストが十分である。
- [ ] ポップアップ背景色と文字色のコントラストが十分である。
