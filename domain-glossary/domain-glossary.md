# AI Agent Domain Glossary

This glossary defines the preferred English and Japanese terms for AI-agent-related documents. Use the preferred terms consistently. Terms listed in `Avoid` are not necessarily forbidden, but should not be used as the primary wording when the preferred term applies.

| English | Japanese | description | Avoid |
|---|---|---|---|
| Agent | エージェント | 指示、ツール、必要に応じたハンドオフやガードレールを持ち、目的達成のために処理を進めるAI実行主体。単なるLLM呼び出しではなく、作業を進める単位を指す。 | AIエージェント, AI agent, agent, 自律エージェント |
| Agentic System | エージェントシステム | エージェント、ワークフロー、ツール、コンテキスト、評価、ガードレールを組み合わせたAI実行システム全体。個々のエージェントではなく、運用可能な仕組み全体を指す。 | AIシステム, agentic system, agentic AI system, エージェント基盤 |
| Workflow | ワークフロー | 開発者があらかじめ決めた手順や分岐に沿って、LLMやツールを組み合わせて実行する処理の流れ。自律的な判断よりも、設計された経路が中心になる。 | agent workflow, 処理フロー, 作業手順, 流れ |
| Single-Agent System | 単一エージェントシステム | ひとつのエージェントがツールやコンテキストを使ってタスクを進める構成。まずこの構成から始め、必要な場合だけマルチエージェント化する。 | single agent, monolithic agent, シンプル構成だけで説明すること |
| Multi-Agent System | マルチエージェントシステム | 複数のエージェントが役割分担、委譲、協調、レビュー、統合を行いながらタスクを解く構成。単一エージェントより複雑になるため、必要性と評価が重要。 | multi-agent, 複数エージェント, agentic system と完全に同義にすること |
| Agent Loop | エージェントループ | エージェントが観察、判断、ツール利用、結果確認、次の行動選択を繰り返す実行サイクル。長い作業や不確実な作業で重要になる。 | loop, 実行ループ, 作業ループ, reasoning loop |
| Automation Level | 自動化レベル | エージェントにどこまで自律的な判断・操作を任せるかの段階。読み取りのみ、提案のみ、承認付き実行、自律実行などで定義する。 | autonomy level と完全に同義にすること, 自動化率, 自律度だけで説明すること |
| Advisory Mode | 提案モード | エージェントが推奨案、下書き、判断材料、次アクションを提示するが、実行は人間が行う自動化レベル。 | advice mode, recommend-only, 提案だけ |
| Approval-Gated Execution | 承認付き実行 | エージェントが操作を準備・提案し、人間またはポリシーの承認後に実行する方式。高リスク操作や外部送信で使う。 | act with approval, approval mode, 人間確認付き実行 |
| Autonomous Execution | 自律実行 | 事前に定めた権限、ガードレール、停止条件、監視の範囲内で、エージェントが人間承認なしに操作を実行する方式。 | full automation, 完全自動化, unattended execution |
| Tool | ツール | エージェントが外部情報を取得したり、環境に作用したりするために呼び出す機能。検索、ファイル操作、API呼び出し、コード実行などを含む。 | 外部ツール, function, API, 道具 |
| Tool Use | ツール利用 | エージェントが目的達成のためにツールを選び、入力を作り、結果を解釈して次の行動に反映すること。単なる関数呼び出しではなく、判断を含む行為を指す。 | tool calling, function calling, ツール呼び出し |
| Tool Call | ツール呼び出し | エージェントやモデルが、特定のツール名と入力を指定して実行を要求すること。Tool Use の中の実行単位として扱う。 | tool use と完全に同義にすること, function calling と完全に同義にすること |
| Tool Definition | ツール定義 | エージェントがツールを正しく選択・実行するために渡す、ツール名、説明、入力スキーマ、返却値、使用条件などの定義。 | tool spec, function definition, API定義 |
| Tool Description | ツール説明 | ツールの目的、使うべき場面、使ってはいけない場面、入力の意味、返却値の読み方をエージェント向けに説明する文章。 | description, 説明文, API説明 |
| Tool Result | ツール結果 | ツール実行後にエージェントへ返す結果。成功/失敗だけでなく、次の判断に必要な情報、エラー理由、推奨アクションを含める。 | result, output, response, 返却値 |
| Tool Surface | ツールサーフェス | エージェントに公開されているツール群、名前空間、引数、説明の全体。広すぎると選択ミスやコンテキスト消費が増えるため、絞り込みが重要になる。 | tool list, available tools, ツール一覧 |
| Tool Permission | ツール権限 | ツールごとに許可される読み取り、書き込み、実行、送信、削除などの操作範囲。ガードレールや人間確認と組み合わせて管理する。 | permission, access, 権限, ツールアクセス |
| Tool Discovery | ツール発見 | エージェントやクライアントが、利用可能なツールの一覧、説明、入力スキーマ、使用条件を取得し、必要に応じて選べるようにすること。 | tool list と完全に同義にすること, retrieval と完全に同義にすること |
| Agent-Computer Interface | - | エージェントがコンピュータ、API、ファイル、アプリケーション、実行環境を扱うためのインターフェース設計。人間向けUI/APIではなく、エージェントが迷わず使える境界を設計する考え方。略称は ACI。 | ACIだけで初出すること, AI向けツール, human API |
| Tool Wrapper | ツールラッパー | 既存APIや複数操作を、エージェントが目的単位で使いやすい形に包み直したツール。人間や通常プログラム向けAPIをそのまま渡さないために使う。 | wrapper, APIラップ, ラッパー |
| Function Calling | - | モデルが定義済みの関数形式ツールを選び、構造化された引数を生成して、外部機能やアプリケーション側の処理と接続する仕組み。OpenAI文脈では実装寄りの語として扱う。 | tool calling と完全に混同すること, 関数呼び出しだけで説明すること |
| Hosted Tool | - | モデル提供側やプラットフォーム側でホストされる検索、ファイル検索、コード実行などの組み込みツール。自前実装の負担を下げられるが、提供環境への依存がある。 | built-in tool, hosted tools, 組み込みツール |
| Suggested Next Action | 推奨次アクション | ツール結果やツールエラーに含める、エージェントが次に取るべき行動の提案。再試行、入力修正、人間確認、別ツール利用、停止などを示す。 | recommendation と完全に同義にすること, error message と完全に同義にすること |
| Context | コンテキスト | エージェントが次の判断や出力に使う情報の集合。システム指示、ユーザー入力、ツール定義、ツール結果、外部データ、会話履歴、作業状態などを含む。 | 文脈, prompt, 入力, 背景情報 |
| Context Engineering | コンテキスト設計 | エージェントが適切に判断できるように、目的、背景、制約、関連情報、ツール結果、成功条件を設計して渡すこと。単なるプロンプト文面ではなく、利用可能な文脈全体を扱う。 | context engineering, 文脈設計, プロンプト設計 |
| Context State | コンテキスト状態 | ある時点でエージェントに渡され、判断に影響しているコンテキスト全体の状態。単発プロンプトではなく、変化し続ける作業状態として扱う。 | state, 状態, working context, コンテキスト全体 |
| Static Context | 静的コンテキスト | 実行中に基本的には変わらない指示や知識。システム指示、役割、ポリシー、固定ルール、リポジトリの恒久的な作法などを指す。 | 固定情報, static information, permanent context |
| Dynamic Context | 動的コンテキスト | 実行中に更新される情報。ユーザーの追加指示、ツール結果、現在の作業状況、途中経過、取得した外部情報などを指す。 | 動的情報, runtime context, current context |
| Session Memory | セッションメモリ | ひとつの会話や作業セッション内で、過去のやり取りや作業状態を保持する短期的なメモリ。複数ターンの一貫性を保つために使う。 | session, conversation memory, 会話履歴だけで説明すること |
| Short-Term Memory | 短期メモリ | 現在のスレッドやセッション内で有効なメモリ。直近の会話、途中状態、現在の目的、未完了タスクなどを保持する。 | STM, thread memory, working memory |
| Long-Term Memory | 長期メモリ | セッションをまたいで保持されるメモリ。ユーザー設定、継続的なプロジェクト知識、過去から再利用すべき事実などを扱う。 | LTM, persistent memory, 永続メモリ |
| Context Compression | コンテキスト圧縮 | 長くなった会話履歴や作業ログから重要情報を残し、不要情報を削って、短く有用な形にまとめ直すこと。 | compression, compaction, summarization, 要約 |
| Context Trimming | コンテキストトリミング | 古い情報、低関連情報、不要な履歴をコンテキストから取り除き、現在の目的に必要な情報を残すこと。 | trimming, pruning, 削除, 履歴カット |
| Retrieval | 検索取得 | 必要なタイミングで外部データ、過去ログ、ドキュメント、長期メモリなどから関連情報を探してコンテキストに追加すること。 | retrieve, search, lookup, 検索だけで説明すること |
| Prompt Chaining | プロンプトチェーン | 複雑なタスクを複数のLLM呼び出しに分け、前の出力を次の入力として渡しながら処理するワークフローパターン。各ステップを検査・調整しやすい。 | prompt chain, chain, チェーン, プロンプト連鎖 |
| Routing | ルーティング | 入力内容や状況に応じて、使用する処理、ツール、モデル、エージェントを選び分けるワークフローパターン。 | route, 分岐, 振り分け, intent routing |
| Parallelization | 並列化 | 複数の処理、LLM呼び出し、ツール実行、エージェント作業を並列に走らせ、速度向上や多面的な検討を行うワークフローパターン。 | parallel execution, 並列実行, parallel pattern |
| Orchestrator-Workers | オーケストレーター・ワーカー | 中央のオーケストレーターがタスクを分解し、複数のワーカーに割り当て、結果を統合するワークフローパターン。 | orchestrator-workers, coordinator-workers, supervisor-workers |
| Evaluator-Optimizer | 評価者・改善者 | 生成結果を評価者が確認し、その評価をもとに改善者が出力を修正する反復型ワークフローパターン。品質改善ループに使う。 | evaluator optimizer, review loop, critique loop, 評価改善ループ |
| Orchestration | オーケストレーション | 複数のステップ、ツール、エージェント、分岐、ハンドオフをどの順番・条件で動かすかを設計し管理すること。 | orchestration, 流れの設計, 司令塔, 実行管理 |
| Task Decomposition | タスク分解 | 大きな目的や曖昧な依頼を、実行可能な小さな作業単位に分けること。ワークフロー設計やマルチエージェント設計の前提になる。 | decomposition, step decomposition, 作業分解, ステップ分解 |
| Handoff | ハンドオフ | あるエージェントや処理ステップから、別の専門エージェントや担当処理へ作業を引き渡すこと。責任の移動と、渡す情報の設計が重要になる。 | handoff, 委譲, 引き継ぎ, agent handoff |
| Delegation | 委譲 | あるエージェントやオーケストレーターが、特定の作業や判断を別のエージェントへ任せること。Handoff より一般的な作業割り当てとして使う。 | handoff と完全に同義にすること, assignment と完全に同義にすること |
| Agent-as-Tool | ツールとしてのエージェント | 中央エージェントが他のエージェントをツールのように呼び出して、特定サブタスクの結果を得る構成。呼び出される側は独立した専門処理を担当する。 | agents as tools, tool agent, handoff と完全に同義にすること |
| Result Synthesis | 結果統合 | 複数エージェントや複数処理から得た結果を比較・要約・矛盾解消し、最終出力や次の判断にまとめること。 | synthesis, integration と完全に同義にすること, まとめだけで説明すること |
| Supervisor Agent | スーパーバイザーエージェント | 複数の専門エージェントの選択、呼び出し、作業配分、結果統合を管理する上位エージェント。階層型マルチエージェント構成で使う。 | supervisor, lead agent, coordinator, manager agent |
| Worker Agent | ワーカーエージェント | スーパーバイザーやオーケストレーターから割り当てられた特定タスクを実行する専門エージェント。 | worker, subagent, specialist agent, 専門エージェント |
| Specialist Agent | 専門エージェント | 特定の領域、作業、判断、ツール利用に特化したエージェント。調査、要約、コード、レビュー、財務分析などの役割を持つ。 | worker agent と完全に同義にすること, subagent と完全に同義にすること |
| Sub-Agent | サブエージェント | あるエージェントやオーケストレーターから呼び出される下位エージェント。専門性を持つ場合もあるが、階層上の位置を表す語として使う。 | specialist agent と完全に同義にすること, child agent, worker と完全に同義にすること |
| Agent Team | エージェントチーム | 共通の目的に対して、複数の専門エージェントやサブエージェントを組み合わせたチーム構成。役割、責任、通信経路、統合方法を明確にする。 | multi-agent system と完全に同義にすること, teamだけで説明すること |
| Shared State | 共有状態 | 複数エージェントが参照・更新する共通の作業状態。進捗、メモ、部分結果、判断履歴などを含み、競合や汚染を防ぐ設計が必要。 | shared memory と完全に同義にすること, state と完全に同義にすること |
| Communication Flow | 通信フロー | エージェント間で、依頼、結果、状態、判断、エラー、承認要求などがどの順番・経路で渡るかを示す流れ。 | message flow と完全に同義にすること, orchestration と完全に同義にすること |
| Evaluation | 評価 | エージェントやワークフローが期待どおりに動いているかを、成功条件、評価ケース、ログ、トレース、人間評価などで確認すること。開発後だけでなく改善サイクルの一部として扱う。 | eval, evals, evaluation, テスト |
| Eval | 評価ケース | エージェントやワークフローの特定の振る舞いを確認するための評価単位。入力、期待される振る舞い、採点方法、合否基準などを含む。 | evaluation と同義にすること, test case, テストケース |
| Eval Suite | 評価スイート | 複数の評価ケースを目的別にまとめた評価セット。品質確認、回帰確認、安全性確認など、用途ごとに分けて運用する。 | evals, evaluation set, test suite |
| Grader | 採点器 | 評価対象の出力や行動を、ルール、人間、LLM、プログラムなどで採点する仕組み。合否だけでなくスコアや理由を返すこともある。 | evaluator, judge, LLM judge, 採点者 |
| Model-Based Grading | モデル採点 | LLMなどのモデルを採点器として使い、出力の品質、正確性、根拠性、安全性などを評価する方法。人間採点の代替または補助として使う。 | LLM judge と完全に同義にすること, grader と完全に同義にすること |
| Evaluation Harness | 評価ハーネス | 評価対象の実行、データセットの投入、採点器の適用、結果集計、トレース保存をまとめて行う評価実行基盤。評価の再現性と継続運用を支える。 | eval harness, test runner と完全に同義にすること |
| Regression Testing | 回帰テスト | プロンプト、モデル、ツール、ワークフロー変更後に、以前できていた振る舞いが壊れていないか確認する評価。 | regression eval, 回帰評価, リグレッションテスト |
| Trace | トレース | 1回のエージェント実行で起きたモデル呼び出し、ツール利用、ハンドオフ、ガードレール、カスタムイベントなどの時系列記録。 | log, 実行履歴, tracing と混同すること |
| Span | スパン | トレース内のひとつの処理区間。モデル呼び出し、ツール実行、ハンドオフなど、開始と終了を持つ単位として記録される。 | event, log entry, step |
| Observability | 観測可能性 | エージェントやLLMアプリケーションの内部動作を、トレース、ログ、メトリクス、評価結果などから理解・調査できる状態や仕組み。 | monitoring と同義にすること, 可観測性, 監視 |
| Feedback Loop | フィードバックループ | エージェントの出力、実行結果、評価、ユーザーフィードバック、運用データを次の改善に戻す仕組み。改善サイクルを継続させるために使う。 | iteration と完全に同義にすること, review loop と完全に同義にすること |
| Evaluation Drift | 評価ドリフト | モデル、データ、ユーザー入力、ツール、プロンプト、業務条件の変化により、過去の評価結果が現在の性能やリスクを表しにくくなること。 | data drift と完全に同義にすること, quality degradation と完全に同義にすること |
| Guardrail | ガードレール | 入力、出力、ツール利用、権限操作などを検査・制御し、エージェントの危険な振る舞いを防ぐための安全制御。 | guardrails, 入力制御, 出力制御, 安全策 |
| Input Guardrail | 入力ガードレール | ユーザー入力やツール実行前の入力を検査し、危険・不正・不適切な内容を検出した場合に、拒否、修正、停止、エスカレーションへ移す制御。 | input validation と完全に同義にすること, moderation と完全に同義にすること |
| Output Guardrail | 出力ガードレール | モデル出力、ツール結果、外部送信前の内容を検査し、不適切な出力、機密情報、危険操作、形式違反を防ぐ制御。 | output validation と完全に同義にすること, post-processing と完全に同義にすること |
| Tripwire | トリップワイヤー | ガードレールが重大な条件違反や危険を検出したときに発火し、実行停止、一時停止、拒否応答、人間レビューなどへ切り替える仕組み。 | alert と完全に同義にすること, stop condition と完全に同義にすること |
| Human Review | 人間レビュー | エージェントの出力、判断、ツール利用、外部送信、高リスク操作などを人間が確認すること。完全自動化せず、人間の判断を挟む安全制御として使う。 | human-in-the-loop, 人間確認, 確認, review |
| Approval | 承認 | エージェントが特定の操作を実行する前に、人間や管理者が明示的に許可すること。特に送信、削除、購入、公開、本番操作などで使う。 | approve, permission, 許可, 確認 |
| Checkpoint | 確認ポイント | ワークフローやエージェントループの途中で、人間レビュー、承認、状態確認、方針変更を行うために設ける停止地点。 | checkpoint, approval point, 確認地点 |
| Escalation | エスカレーション | エージェントが自力で判断・処理すべきでない状況を、人間、管理者、専門担当、別システムに引き上げること。 | escalate, 引き上げ, 相談, 人に回す |
| Stop Condition | 停止条件 | エージェント実行を続けず、停止・拒否・エスカレーション・人間確認に移るべき条件。危険操作、権限不足、不確実性、失敗回数などで定義する。 | checkpoint と完全に同義にすること, end condition, 終了条件 |
| Safe Failure | 安全な失敗 | 不確実性、エラー、権限不足、危険操作、判断不能が起きたときに、被害を広げず、停止・確認・エスカレーションできる失敗の仕方。 | fail-safe と完全に同義にすること, ただ停止すること |
