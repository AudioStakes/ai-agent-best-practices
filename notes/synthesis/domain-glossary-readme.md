## 作成手順

このナレッジベースは、保存したAIエージェント関連記事のMarkdownをもとに、ChatGPTとの対話で段階的に作成したものです。

作成の流れは以下です。

```text
記事本文のMarkdown保存
↓
記事ごとの価値評価
↓
重要記事の絞り込み
↓
重要記事の要約
↓
タグ分類・重み付け
↓
タグ別の横断分析
↓
Markdown知識ベース化
↓
ドメイン用語候補の洗い出し
↓
10語ずつの確認による代表語・日本語表記・説明・Avoidの決定
↓
一般的なソフトウェアエンジニアリング用語を削除
↓
AIエージェント固有、または表記・意味が分かれやすい用語に絞り込み
```

### 前提

リポジトリで記事本文をMarkdownとして保存できる状態にしておきます。

ローカルで以下を実行します。

```bash
npm run save:content
```

これにより、記事本文が以下のような場所に保存されます。

```text
content/
  openai/
  anthropic/
  google-cloud/
  langchain/
  ...
assets/
  ...
```

以降は、保存されたMarkdown群をChatGPTに渡し、対話しながら知識ベースを作成します。

### Step 1. 記事の価値を5段階評価する

保存したMarkdown群をChatGPTに渡し、AIエージェントのベストプラクティスとして価値があるかを評価します。

```text
マークダウンとして保存しました。
このマークダウンを見て、AIエージェントのベストプラクティスとして価値のある記事かどうかを5段階評価で教えてください。
```

評価基準は以下です。

```text
5: 非常に価値が高い
4: 価値が高い
3: 補助的
2: 関連はあるが弱い
1: 今回の目的にはあまり向かない
```

以降の分析では、基本的に評価4以上の記事を対象にします。

### Step 2. 評価4以上の記事を要約する

評価4以上の記事だけに絞り、記事ごとに短く要約します。

```text
評価4以上に絞ってください。
それらの記事を5行くらいで要約してください。
```

この時点で、後続の分類・タグ付けに使う重要記事リストを確定します。

### Step 3. 重要記事をタグ付けする

評価4以上の記事を、1記事1カテゴリではなく、複数タグで分類します。

AIエージェント関連記事は、設計・評価・ツール・セキュリティなどの観点が重なりやすいため、タグには重みを付けます。

```text
評価4以上に絞った記事を分類してください。
分類するのが難しければ、タグ付けしてください。
そのタグに重み付けしてください。
```

タグの重みは以下です。

```text
5 = その記事の中心テーマ
4 = かなり重要なテーマ
3 = 明確に含まれるテーマ
2 = 補助的に含まれるテーマ
1 = 少し関係する程度
```

このプロセスで、以下の10タグに整理しました。

```text
1. agent_design
2. workflow_design
3. tool_use
4. context_engineering
5. evals
6. coding_agents
7. production_operations
8. security_sandboxing
9. multi_agent
10. governance
```

### Step 4. タグごとに横断分析する

10個のタグについて、1つずつChatGPTに深掘りを依頼します。

ここでは単なる記事要約ではなく、タグに関連する記事を横断して、以下を整理します。

```text
- どの記事でも共通する重要点
- OpenAIとAnthropicで共通する重要点
- OpenAIのみで強調される重要点
- Anthropicのみで強調される重要点
- 各ポイントの重要度
```

各タグについて、以下の `<番号>` と `<タグ名>` を差し替えて使います。

```text
<番号>. <タグ名> では何が大事ですか？

このタグの記事を一つ一つ読み以下の分類でまとめてください。

* どの記事でも共通
* OpenAIとAnthropicで共通
* OpenAIのみ
* Anthropicのみ

さらに、それぞれの大事な点の重要度も重み付けしてください。
OpenAIとAnthropicで共通していても、重要ではないなら気にしなくて良い、という判断をできるようにしたいからです。
```

分析対象タグは以下です。

| 番号 | タグ名             | 主に整理する観点                      |
| -: | --------------- | ----------------------------- |
|  1 | エージェント設計系       | エージェントが必要か、設計パターン、ツール・評価・人間確認 |
|  2 | ワークフロー設計系       | ステップ分解、役割分担、固定フロー、分岐、レビュー     |
|  3 | ツール利用系          | AI向けツール設計、責務、説明文、返却値、安全策      |
|  4 | コンテキスト設計系       | 必要情報、関連性、構造化、成功条件、ツール結果       |
|  5 | 評価系             | 成功条件、評価データ、途中過程、回帰評価、改善       |
|  6 | コーディングエージェント系   | リポジトリ文脈、調査・計画、テスト、権限、安全性      |
|  7 | 本番運用系           | PoCとの差、監視、ログ、失敗時対応、承認         |
|  8 | セキュリティ・サンドボックス系 | 最小権限、隔離、secrets保護、確認、環境で守る    |
|  9 | マルチエージェント系      | 役割分担、情報共有、司令塔、統合、ログ           |
| 10 | ガバナンス系          | 利用範囲、責任者、データ管理、権限、監査          |

### Step 5. Markdownファイルとして保存する

タグ別の横断分析結果を、以下の構成で保存します。

```text
knowledge/
  README.md
  tag-guides/
    01-agent-design.md
    02-workflow-design.md
    03-tool-use.md
    04-context-engineering.md
    05-evals.md
    06-coding-agents.md
    07-production-operations.md
    08-security-sandboxing.md
    09-multi-agent.md
    10-governance.md
```

`content/` は元記事本文、`knowledge/` は記事を横断して統合した知見、という役割分担にします。

### Step 6. テンプレートに整形してZIP化する

作成した `knowledge/` フォルダをZIP化し、ChatGPTに渡してテンプレート構造に整形します。

```text
ここまで出力してもらった内容を添付ファイルのようにまとめました。
このマークダウンの中身を、次のようなテンプレートに当てはめてください。
出力はzipでお願いします。

# 01. エージェント設計系

## 対象タグ

`agent_design`

## 対象記事

- Anthropic — Building Effective AI Agents
- OpenAI — Building agents
- Google Cloud — Choose a design pattern for your agentic AI system
- ...

## 結論

...

## どの記事でも共通

### 1. ...
**重要度: 5**

...

## OpenAIとAnthropicで共通

### 1. ...
**重要度: 5**

...

## OpenAIのみ

...

## Anthropicのみ

...

## 実務で重要な順

| 重要度 | ポイント | 判断への使い方 |
|---:|---|---|
| 5 | ... | ... |

## 一言でいうと

...
```

最終的に、以下のZIPを生成します。

```text
knowledge_templated.zip
```

ZIP内の構成は以下です。

```text
knowledge/
  README.md
  tag-guides/
    01-agent-design.md
    02-workflow-design.md
    03-tool-use.md
    04-context-engineering.md
    05-evals.md
    06-coding-agents.md
    07-production-operations.md
    08-security-sandboxing.md
    09-multi-agent.md
    10-governance.md
```

### Step 7. ドメイン用語集を作成する

テンプレート化した `tag-guides/` 配下のMarkdownをもとに、ドメイン用語集を作成します。

最初に、似た意味で使われている単語、表記揺れ、近い概念を広く洗い出します。

```text
添付ファイルのtag-guidesフォルダ内のマークダウンのドメイン用語集を作りたいです。
まずは表記揺れといいますか、似たような意味で使われている単語をすべてリストアップしてください。
ここではまずドメインを定義することは考えず、似た意味で使われていそうな単語をとにかく洗い出すことに集中してください。
```

次に、`grill-with-docs` の進め方に沿って、10語ずつ代表語・日本語表記・説明・Avoidを確認します。

```text
それらのドメイン用語を決めていきましょう。
最終的なアウトプットは CONTEXT-FORMAT.md に沿ったフォーマットにしたいです。
ただし、英語と日本語の両方に対応したドメイン用語にします。
そのため表形式で

English | Japanese | description | Avoid

となるようにまとめてください。

質問は10個ずつにしてください。
おすすめの回答を考えるとき、最適なドメイン用語をネットで調べてください。
調べた結果も載せてください。
おすすめの回答以外がある場合のみ回答します。
それ以外はおすすめの回答を受け入れたとみなしてください。
```

この対話で、最初は周辺概念も含めて広く候補を確認します。
その後、以下の基準で最終的なドメイン用語を絞り込みます。

```text
- ソフトウェアエンジニアの一般常識は載せない
- AIエージェントに関するドメイン用語を残す
- ソフトウェアエンジニアでも人によって表記が分かれたり、意味がまだ十分に浸透していないものを残す
- 一般的なソフトウェア開発、セキュリティ、法務、運用、データ管理の用語は削る
```

できあがった用語集は、以下に保存します。

```text
knowledge/domain-glossary.md
```

### できあがるもの

この手順で作成する `knowledge_templated.zip` は、元記事本文をそのまま変換したものではありません。

保存した記事をもとに、ChatGPTとの対話で以下を行った成果物です。

```text
記事単位の評価
↓
重要記事への絞り込み
↓
記事単位の要約
↓
タグ分類
↓
タグ別の横断分析
↓
OpenAI / Anthropic / 他記事の共通点・差分整理
↓
重要度付きの実践ポイント化
↓
Markdown知識ベース化
↓
ドメイン用語候補の洗い出し
↓
代表語・日本語表記・説明・Avoidの決定
↓
AIエージェント文脈に必要な用語への絞り込み
```

つまり、このZIPは、AIエージェントのベストプラクティス記事を横断的に整理したタグ別ナレッジベースと、その知識ベースを読むためのドメイン用語集です。
