AI Agent Domain Glossary

This glossary defines the preferred English and Japanese terms for AI-agent-related documents. Use the preferred terms consistently. Terms listed in Avoid are not necessarily forbidden, but should not be used as the primary wording when the preferred term applies.

  • Agentエージェント

    説明: 指示、ツール、必要に応じたハンドオフやガードレールを持ち、目的達成のために処理を進めるAI実行主体。単なるLLM呼び出しではなく、作業を進める単位を指す。

    Avoid: AIエージェント, AI agent, agent, 自律エージェント

  • Agentic Systemエージェントシステム

    説明: エージェント、ワークフロー、ツール、コンテキスト、評価、ガードレールを組み合わせたAI実行システム全体。個々のエージェントではなく、運用可能な仕組み全体を指す。

    Avoid: AIシステム, agentic system, agentic AI system, エージェント基盤

  • Workflowワークフロー

    説明: 開発者があらかじめ決めた手順や分岐に沿って、LLMやツールを組み合わせて実行する処理の流れ。自律的な判断よりも、設計された経路が中心になる。

    Avoid: agent workflow, 処理フロー, 作業手順, 流れ

  • Single-Agent System単一エージェントシステム

    説明: ひとつのエージェントがツールやコンテキストを使ってタスクを進める構成。まずこの構成から始め、必要な場合だけマルチエージェント化する。

    Avoid: single agent, monolithic agent, シンプル構成だけで説明すること

  • Multi-Agent Systemマルチエージェントシステム

    説明: 複数のエージェントが役割分担、委譲、協調、レビュー、統合を行いながらタスクを解く構成。単一エージェントより複雑になるため、必要性と評価が重要。

    Avoid: multi-agent, 複数エージェント, agentic system と完全に同義にすること

  • Agent Loopエージェントループ

    説明: エージェントが観察、判断、ツール利用、結果確認、次の行動選択を繰り返す実行サイクル。長い作業や不確実な作業で重要になる。

    Avoid: loop, 実行ループ, 作業ループ, reasoning loop

  • Automation Level自動化レベル

    説明: エージェントにどこまで自律的な判断・操作を任せるかの段階。読み取りのみ、提案のみ、承認付き実行、自律実行などで定義する。

    Avoid: autonomy level と完全に同義にすること, 自動化率, 自律度だけで説明すること

  • Advisory Mode提案モード

    説明: エージェントが推奨案、下書き、判断材料、次アクションを提示するが、実行は人間が行う自動化レベル。

    Avoid: advice mode, recommend-only, 提案だけ

  • Approval-Gated Execution承認付き実行

    説明: エージェントが操作を準備・提案し、人間またはポリシーの承認後に実行する方式。高リスク操作や外部送信で使う。

    Avoid: act with approval, approval mode, 人間確認付き実行

  • Autonomous Execution自律実行

    説明: 事前に定めた権限、ガードレール、停止条件、監視の範囲内で、エージェントが人間承認なしに操作を実行する方式。

    Avoid: full automation, 完全自動化, unattended execution

  • Toolツール

    説明: エージェントが外部情報を取得したり、環境に作用したりするために呼び出す機能。検索、ファイル操作、API呼び出し、コード実行などを含む。

    Avoid: 外部ツール, function, API, 道具

  • Tool Useツール利用

    説明: エージェントが目的達成のためにツールを選び、入力を作り、結果を解釈して次の行動に反映すること。単なる関数呼び出しではなく、判断を含む行為を指す。

    Avoid: tool calling, function calling, ツール呼び出し

  • Tool Callツール呼び出し

    説明: エージェントやモデルが、特定のツール名と入力を指定して実行を要求すること。Tool Use の中の実行単位として扱う。

    Avoid: tool use と完全に同義にすること, function calling と完全に同義にすること

  • Tool Definitionツール定義

    説明: エージェントがツールを正しく選択・実行するために渡す、ツール名、説明、入力スキーマ、返却値、使用条件などの定義。

    Avoid: tool spec, function definition, API定義

  • Tool Descriptionツール説明

    説明: ツールの目的、使うべき場面、使ってはいけない場面、入力の意味、返却値の読み方をエージェント向けに説明する文章。

    Avoid: description, 説明文, API説明

  • Tool Resultツール結果

    説明: ツール実行後にエージェントへ返す結果。成功/失敗だけでなく、次の判断に必要な情報、エラー理由、推奨アクションを含める。

    Avoid: result, output, response, 返却値

  • Tool Surfaceツールサーフェス

    説明: エージェントに公開されているツール群、名前空間、引数、説明の全体。広すぎると選択ミスやコンテキスト消費が増えるため、絞り込みが重要になる。

    Avoid: tool list, available tools, ツール一覧

  • Tool Permissionツール権限

    説明: ツールごとに許可される読み取り、書き込み、実行、送信、削除などの操作範囲。ガードレールや人間確認と組み合わせて管理する。

    Avoid: permission, access, 権限, ツールアクセス

  • Tool Discoveryツール発見

    説明: エージェントやクライアントが、利用可能なツールの一覧、説明、入力スキーマ、使用条件を取得し、必要に応じて選べるようにすること。

    Avoid: tool list と完全に同義にすること, retrieval と完全に同義にすること

  • Agent-Computer Interface-

    説明: エージェントがコンピュータ、API、ファイル、アプリケーション、実行環境を扱うためのインターフェース設計。人間向けUI/APIではなく、エージェントが迷わず使える境界を設計する考え方。略称は ACI。

    Avoid: ACIだけで初出すること, AI向けツール, human API

  • Tool Wrapperツールラッパー

    説明: 既存APIや複数操作を、エージェントが目的単位で使いやすい形に包み直したツール。人間や通常プログラム向けAPIをそのまま渡さないために使う。

    Avoid: wrapper, APIラップ, ラッパー

  • Function Calling-

    説明: モデルが定義済みの関数形式ツールを選び、構造化された引数を生成して、外部機能やアプリケーション側の処理と接続する仕組み。OpenAI文脈では実装寄りの語として扱う。

    Avoid: tool calling と完全に混同すること, 関数呼び出しだけで説明すること

  • Hosted Tool-

    説明: モデル提供側やプラットフォーム側でホストされる検索、ファイル検索、コード実行などの組み込みツール。自前実装の負担を下げられるが、提供環境への依存がある。

    Avoid: built-in tool, hosted tools, 組み込みツール

  • Suggested Next Action推奨次アクション

    説明: ツール結果やツールエラーに含める、エージェントが次に取るべき行動の提案。再試行、入力修正、人間確認、別ツール利用、停止などを示す。

    Avoid: recommendation と完全に同義にすること, error message と完全に同義にすること

  • Contextコンテキスト

    説明: エージェントが次の判断や出力に使う情報の集合。システム指示、ユーザー入力、ツール定義、ツール結果、外部データ、会話履歴、作業状態などを含む。

    Avoid: 文脈, prompt, 入力, 背景情報

  • Context Engineeringコンテキスト設計

    説明: エージェントが適切に判断できるように、目的、背景、制約、関連情報、ツール結果、成功条件を設計して渡すこと。単なるプロンプト文面ではなく、利用可能な文脈全体を扱う。

    Avoid: context engineering, 文脈設計, プロンプト設計

  • Context Stateコンテキスト状態

    説明: ある時点でエージェントに渡され、判断に影響しているコンテキスト全体の状態。単発プロンプトではなく、変化し続ける作業状態として扱う。

    Avoid: state, 状態, working context, コンテキスト全体

  • Static Context静的コンテキスト

    説明: 実行中に基本的には変わらない指示や知識。システム指示、役割、ポリシー、固定ルール、リポジトリの恒久的な作法などを指す。

    Avoid: 固定情報, static information, permanent context

  • Dynamic Context動的コンテキスト

    説明: 実行中に更新される情報。ユーザーの追加指示、ツール結果、現在の作業状況、途中経過、取得した外部情報などを指す。

    Avoid: 動的情報, runtime context, current context

  • Session Memoryセッションメモリ

    説明: ひとつの会話や作業セッション内で、過去のやり取りや作業状態を保持する短期的なメモリ。複数ターンの一貫性を保つために使う。

    Avoid: session, conversation memory, 会話履歴だけで説明すること

  • Short-Term Memory短期メモリ

    説明: 現在のスレッドやセッション内で有効なメモリ。直近の会話、途中状態、現在の目的、未完了タスクなどを保持する。

    Avoid: STM, thread memory, working memory

  • Long-Term Memory長期メモリ

    説明: セッションをまたいで保持されるメモリ。ユーザー設定、継続的なプロジェクト知識、過去から再利用すべき事実などを扱う。

    Avoid: LTM, persistent memory, 永続メモリ

  • Context Compressionコンテキスト圧縮

    説明: 長くなった会話履歴や作業ログから重要情報を残し、不要情報を削って、短く有用な形にまとめ直すこと。

    Avoid: compression, compaction, summarization, 要約

  • Context Trimmingコンテキストトリミング

    説明: 古い情報、低関連情報、不要な履歴をコンテキストから取り除き、現在の目的に必要な情報を残すこと。

    Avoid: trimming, pruning, 削除, 履歴カット

  • Retrieval検索取得

    説明: 必要なタイミングで外部データ、過去ログ、ドキュメント、長期メモリなどから関連情報を探してコンテキストに追加すること。

    Avoid: retrieve, search, lookup, 検索だけで説明すること

  • Prompt Chainingプロンプトチェーン

    説明: 複雑なタスクを複数のLLM呼び出しに分け、前の出力を次の入力として渡しながら処理するワークフローパターン。各ステップを検査・調整しやすい。

    Avoid: prompt chain, chain, チェーン, プロンプト連鎖

  • Routingルーティング

    説明: 入力内容や状況に応じて、使用する処理、ツール、モデル、エージェントを選び分けるワークフローパターン。

    Avoid: route, 分岐, 振り分け, intent routing

  • Parallelization並列化

    説明: 複数の処理、LLM呼び出し、ツール実行、エージェント作業を並列に走らせ、速度向上や多面的な検討を行うワークフローパターン。

    Avoid: parallel execution, 並列実行, parallel pattern

  • Orchestrator-Workersオーケストレーター・ワーカー

    説明: 中央のオーケストレーターがタスクを分解し、複数のワーカーに割り当て、結果を統合するワークフローパターン。

    Avoid: orchestrator-workers, coordinator-workers, supervisor-workers

  • Evaluator-Optimizer評価者・改善者

    説明: 生成結果を評価者が確認し、その評価をもとに改善者が出力を修正する反復型ワークフローパターン。品質改善ループに使う。

    Avoid: evaluator optimizer, review loop, critique loop, 評価改善ループ

  • Orchestrationオーケストレーション

    説明: 複数のステップ、ツール、エージェント、分岐、ハンドオフをどの順番・条件で動かすかを設計し管理すること。

    Avoid: orchestration, 流れの設計, 司令塔, 実行管理

  • Task Decompositionタスク分解

    説明: 大きな目的や曖昧な依頼を、実行可能な小さな作業単位に分けること。ワークフロー設計やマルチエージェント設計の前提になる。

    Avoid: decomposition, step decomposition, 作業分解, ステップ分解

  • Handoffハンドオフ

    説明: あるエージェントや処理ステップから、別の専門エージェントや担当処理へ作業を引き渡すこと。責任の移動と、渡す情報の設計が重要になる。

    Avoid: handoff, 委譲, 引き継ぎ, agent handoff

  • Delegation委譲

    説明: あるエージェントやオーケストレーターが、特定の作業や判断を別のエージェントへ任せること。Handoff より一般的な作業割り当てとして使う。

    Avoid: handoff と完全に同義にすること, assignment と完全に同義にすること

  • Agent-as-Toolツールとしてのエージェント

    説明: 中央エージェントが他のエージェントをツールのように呼び出して、特定サブタスクの結果を得る構成。呼び出される側は独立した専門処理を担当する。

    Avoid: agents as tools, tool agent, handoff と完全に同義にすること

  • Result Synthesis結果統合

    説明: 複数エージェントや複数処理から得た結果を比較・要約・矛盾解消し、最終出力や次の判断にまとめること。

    Avoid: synthesis, integration と完全に同義にすること, まとめだけで説明すること

  • Supervisor Agentスーパーバイザーエージェント

    説明: 複数の専門エージェントの選択、呼び出し、作業配分、結果統合を管理する上位エージェント。階層型マルチエージェント構成で使う。

    Avoid: supervisor, lead agent, coordinator, manager agent

  • Worker Agentワーカーエージェント

    説明: スーパーバイザーやオーケストレーターから割り当てられた特定タスクを実行する専門エージェント。

    Avoid: worker, subagent, specialist agent, 専門エージェント

  • Specialist Agent専門エージェント

    説明: 特定の領域、作業、判断、ツール利用に特化したエージェント。調査、要約、コード、レビュー、財務分析などの役割を持つ。

    Avoid: worker agent と完全に同義にすること, subagent と完全に同義にすること

  • Sub-Agentサブエージェント

    説明: あるエージェントやオーケストレーターから呼び出される下位エージェント。専門性を持つ場合もあるが、階層上の位置を表す語として使う。

    Avoid: specialist agent と完全に同義にすること, child agent, worker と完全に同義にすること

  • Agent Teamエージェントチーム

    説明: 共通の目的に対して、複数の専門エージェントやサブエージェントを組み合わせたチーム構成。役割、責任、通信経路、統合方法を明確にする。

    Avoid: multi-agent system と完全に同義にすること, teamだけで説明すること

  • Shared State共有状態

    説明: 複数エージェントが参照・更新する共通の作業状態。進捗、メモ、部分結果、判断履歴などを含み、競合や汚染を防ぐ設計が必要。

    Avoid: shared memory と完全に同義にすること, state と完全に同義にすること

  • Communication Flow通信フロー

    説明: エージェント間で、依頼、結果、状態、判断、エラー、承認要求などがどの順番・経路で渡るかを示す流れ。

    Avoid: message flow と完全に同義にすること, orchestration と完全に同義にすること

  • Evaluation評価

    説明: エージェントやワークフローが期待どおりに動いているかを、成功条件、評価ケース、ログ、トレース、人間評価などで確認すること。開発後だけでなく改善サイクルの一部として扱う。

    Avoid: eval, evals, evaluation, テスト

  • Eval評価ケース

    説明: エージェントやワークフローの特定の振る舞いを確認するための評価単位。入力、期待される振る舞い、採点方法、合否基準などを含む。

    Avoid: evaluation と同義にすること, test case, テストケース

  • Eval Suite評価スイート

    説明: 複数の評価ケースを目的別にまとめた評価セット。品質確認、回帰確認、安全性確認など、用途ごとに分けて運用する。

    Avoid: evals, evaluation set, test suite

  • Grader採点器

    説明: 評価対象の出力や行動を、ルール、人間、LLM、プログラムなどで採点する仕組み。合否だけでなくスコアや理由を返すこともある。

    Avoid: evaluator, judge, LLM judge, 採点者

  • Model-Based Gradingモデル採点

    説明: LLMなどのモデルを採点器として使い、出力の品質、正確性、根拠性、安全性などを評価する方法。人間採点の代替または補助として使う。

    Avoid: LLM judge と完全に同義にすること, grader と完全に同義にすること

  • Evaluation Harness評価ハーネス

    説明: 評価対象の実行、データセットの投入、採点器の適用、結果集計、トレース保存をまとめて行う評価実行基盤。評価の再現性と継続運用を支える。

    Avoid: eval harness, test runner と完全に同義にすること

  • Regression Testing回帰テスト

    説明: プロンプト、モデル、ツール、ワークフロー変更後に、以前できていた振る舞いが壊れていないか確認する評価。

    Avoid: regression eval, 回帰評価, リグレッションテスト

  • Traceトレース

    説明: 1回のエージェント実行で起きたモデル呼び出し、ツール利用、ハンドオフ、ガードレール、カスタムイベントなどの時系列記録。

    Avoid: log, 実行履歴, tracing と混同すること

  • Spanスパン

    説明: トレース内のひとつの処理区間。モデル呼び出し、ツール実行、ハンドオフなど、開始と終了を持つ単位として記録される。

    Avoid: event, log entry, step

  • Observability観測可能性

    説明: エージェントやLLMアプリケーションの内部動作を、トレース、ログ、メトリクス、評価結果などから理解・調査できる状態や仕組み。

    Avoid: monitoring と同義にすること, 可観測性, 監視

  • Feedback Loopフィードバックループ

    説明: エージェントの出力、実行結果、評価、ユーザーフィードバック、運用データを次の改善に戻す仕組み。改善サイクルを継続させるために使う。

    Avoid: iteration と完全に同義にすること, review loop と完全に同義にすること

  • Evaluation Drift評価ドリフト

    説明: モデル、データ、ユーザー入力、ツール、プロンプト、業務条件の変化により、過去の評価結果が現在の性能やリスクを表しにくくなること。

    Avoid: data drift と完全に同義にすること, quality degradation と完全に同義にすること

  • Guardrailガードレール

    説明: 入力、出力、ツール利用、権限操作などを検査・制御し、エージェントの危険な振る舞いを防ぐための安全制御。

    Avoid: guardrails, 入力制御, 出力制御, 安全策

  • Input Guardrail入力ガードレール

    説明: ユーザー入力やツール実行前の入力を検査し、危険・不正・不適切な内容を検出した場合に、拒否、修正、停止、エスカレーションへ移す制御。

    Avoid: input validation と完全に同義にすること, moderation と完全に同義にすること

  • Output Guardrail出力ガードレール

    説明: モデル出力、ツール結果、外部送信前の内容を検査し、不適切な出力、機密情報、危険操作、形式違反を防ぐ制御。

    Avoid: output validation と完全に同義にすること, post-processing と完全に同義にすること

  • Tripwireトリップワイヤー

    説明: ガードレールが重大な条件違反や危険を検出したときに発火し、実行停止、一時停止、拒否応答、人間レビューなどへ切り替える仕組み。

    Avoid: alert と完全に同義にすること, stop condition と完全に同義にすること

  • Human Review人間レビュー

    説明: エージェントの出力、判断、ツール利用、外部送信、高リスク操作などを人間が確認すること。完全自動化せず、人間の判断を挟む安全制御として使う。

    Avoid: human-in-the-loop, 人間確認, 確認, review

  • Approval承認

    説明: エージェントが特定の操作を実行する前に、人間や管理者が明示的に許可すること。特に送信、削除、購入、公開、本番操作などで使う。

    Avoid: approve, permission, 許可, 確認

  • Checkpoint確認ポイント

  • Stop Condition停止条件

    説明: エージェント実行を続けず、停止・拒否・エスカレーション・人間確認に移るべき条件。危険操作、権限不足、不確実性、失敗回数などで定義する。

  • Refusal拒否応答

  • Prompt Injectionプロンプトインジェクション

    説明: ユーザー入力、外部文書、Webページ、ツール結果などに紛れた悪意ある指示によって、エージェントの判断や出力、ツール利用を意図しない方向へ操作する攻撃。

    Avoid: injection, プロンプト攻撃, 脱獄と同義にすること

  • Indirect Prompt Injection間接プロンプトインジェクション

    説明: エージェントが読む外部文書、Webページ、メール、チケット、ツール結果などを経由して混入するプロンプトインジェクション。ユーザーが直接入力していない点が特徴。

    Avoid: indirect injection, 外部文書攻撃, prompt injection と完全に同義にすること

  • Jailbreak脱獄

    説明: モデルやエージェントに設定された安全制約、ポリシー、出力制限を回避させようとする攻撃や入力。Prompt Injection とは重なるが、主に制約回避に焦点がある。

    Avoid: prompt injection と完全に同義にすること, 制限解除

  • Untrusted Content信頼しないコンテンツ

    説明: 外部文書、Webページ、メール、ユーザー投稿、ツール結果など、内部指示として扱ってはいけない入力。内容は参照できるが、命令としては信頼しない。

    Avoid: external content, 外部コンテンツ, 信頼できない情報

  • Sensitive Information機密情報

    説明: 漏洩・不正利用・不適切な共有によって個人、顧客、組織、事業に損害を与え得る情報。個人情報、認証情報、契約情報、社内機密などを含む。

  • Credential認証情報

    Avoid: credentials, secret, token, password と同義にすること

  • Data Exfiltrationデータ持ち出し

    説明: 機密情報、個人データ、社内資料、コード、ログなどが、意図しない外部宛先や許可されていない場所へ送られること。

    Avoid: tool injection, poisoned tool, prompt injection と完全に同義にすること

  • Excessive Agency過剰な自律性

    Avoid: automation bias と完全に同義にすること, 盲信

    Avoid: section と完全に同義にすること, paragraph と完全に同義にすること

  • Embedding埋め込み

    Avoid: vector database と完全に同義にすること, knowledge base と完全に同義にすること

  • Semantic Search意味検索

    説明: キーワード一致だけでなく、Embedding などを使って意味的に近い情報を検索する方法。表現揺れや類似概念の検索に強い。

    説明: クエリに対して関連するドキュメント、チャンク、リソースを取得する部品。検索方式、フィルタ、ランキング、権限制御などを含むことがある。

    Avoid: retrieval と完全に同義にすること, search engine と完全に同義にすること

  • Reranking再ランキング

    説明: 検索で取得した候補を、関連性、信頼性、回答への有用性などに基づいて並べ替える処理。回答品質や引用精度に影響する。

    Avoid: ranking と完全に同義にすること, sortingだけで説明すること

  • Groundingグラウンディング

    説明: モデルの回答や判断を、検索取得したソース、ツール結果、データベース、引用可能な根拠に接続すること。幻覚を減らし、検証可能性を高める。

    Avoid: citation と完全に同義にすること, retrieval と完全に同義にすること

    説明: 回答、判断、評価、承認の裏付けとして使う具体的な情報。引用箇所、検索結果、ツール結果、ログ、評価結果などを含む。

    Avoid: source と完全に同義にすること, citation と完全に同義にすること

  • Citation引用

    説明: 回答や説明の根拠として、どの情報源・箇所に基づいたかを示す表示。ユーザーやレビュアーが根拠を確認できるようにする。
